> `scripts/risk-guard.mjs` 为准，两者冲突时以更保守的为准。

## 1. 根因分析

1. **直连 wapi**：缺少页面 XHR 自带的完整请求头、风控参数和真实时序，特征明显。
2. **短时间高频**：80 次请求约 2 分钟完成，远超真人节奏。
3. **匀速、单一行为**：只有"搜索翻页"一种动作，没有浏览、停留、回看等混合行为。
4. **接口返回的是结构化数据**：`code 37` 说明平台在网关层就识别了异常环境。

## 2. 硬规则

### 2.1 绝对不做（Never）

1. **不直接请求任何 `/wapi/...` 内部接口**（搜索、详情、公司、聊天）。
2. 不用 headless / 无头浏览器，不用 Playwright/Puppeteer/Selenium 另起浏览器。
3. 不并发：同一时间只开 1 个标签页、1 个账号、串行操作。
4. 不在 23:00–07:00 运行。
5. **收到任何风险提示后不重试、不重新登录、不换 IP、不换账号**。
6. 不群发同一句话术；不群发链接/附件。
7. 不处理验证码/滑块（交给用户手动完成）。
8. 不导出、不传播简历、聊天记录、联系方式。
9. 不把账号、Cookie、Token 交给任何第三方工具或"代投"服务。
10. 不做 7×24 无人值守。

### 2.2 必须做（Always）

1. 只通过 **ego lite 的真实浏览器页面**操作（已登录 Profile）。
2. 每个动作之间 **6–12 秒随机间隔**；每批最多 **30 个页面**。
3. 每批之间休息 **5–10 分钟**；每天最多 **4 批**采集。
4. 进详情页后先**滚动/停留 2–4 秒**再抓取，模拟阅读。
5. 搜索列表滚动 **2.5–4.5 秒/次**，单次最多 **15 屏**，一次最多 **3 个关键词**。
6. 投递：**30 条/天**，**30–90 秒/条**，分 3 个时段（上午/下午/晚上）。
7. 话术必须轮换模板并注入公司/岗位事实，禁止一字不差群发。
8. 遇风险信号**立即停止**并写入冷却状态（24 小时）。
9. 每天先看"剩余沟通次数"，**用到 80% 即停**。
10. 所有动作写日志，能追溯每一步。

## 4. 风险信号与处置

### 4.1 信号

| 信号 | 含义 | 级别 |
|---|---|---|
| `code 37` / "环境存在异常" | 环境风控 | P0 |
| `code 36` / "账号存在风险" | 账号风控 | P0 |
| `code 9` / "访问过于频繁" | 频率限制 | P1 |
| "请完成安全验证" / 滑块 | 验证码挑战 | P1（人工处理） |
| "今日沟通已达上限" / "次数已用完" | 额度耗尽 | P1 |
| 跳转登录页 / "请先登录" | 登录失效 | P1 |
| 连续 3 次页面加载失败 | 环境异常 | P1 |
| 搜索列表为空但 URL 正常 | 可能被限流 | P2 |

> 注意：URL 出现 `_security_check=...` 是 BOSS 的常规挑战参数，**不代表被封**。
> 看到它不要刷新、不要重新登录，正常完成当前浏览即可。

### 4.2 处置

1. **立即停止**当前脚本，不重试。
2. 写入 `data/risk_state.json`：时间、原因、来源步骤。
3. 设置冷却：P0 = 24 小时；P1 = 2–4 小时；二次 P0 = 72 小时。
4. 通知用户，由用户决定是否手动处理验证码/登录。
5. 冷却结束后，先做 **1 次搜索 + 5 个详情** 试探，再恢复批量。

---

## 5. 恢复 Runbook

1. 冷却期内不进行任何自动化操作。
2. 用户手动打开 ego，正常浏览 5–10 分钟、回复几条消息。
3. 检查登录状态（右上角头像、消息页可打开）。
4. 次日先用最小动作试探：1 个关键词、1 屏滚动、5 个详情页。
5. 无异常再恢复到 30 页/批。
6. 再次触发 → 冷却 72 小时，并考虑暂停自动投递，改为半自动。

---

## 6. 投递红线

1. 只投"审核结果 = 通过"的职位。
2. 投递前 4 道校验：
   - 详情页显示"招聘中"；
   - "立即沟通"可用，未显示"职位已关闭/停止招聘"；
   - HR 活跃度不是"半年前/3 个月前"；
   - 不是猎头/代招/外包。
3. 跳过：已关闭/停招、要求博士、猎头代招、HR 暂缓名单。
4. **先做 1 条试投**，确认 BOSS 是"点击即自动发招呼语"还是"可编辑后发送"，再决定批量方式。
5. 投递记录必须落盘：职位 ID、时间、结果、失败原因。
6. **同一公司当天最多投 1 个岗位**，优先投老板/负责人发布的那条，避免被判定为骚扰。
7. 已经聊过的 HR/公司不重复投（查聊天列表和 `relationInfo`）。
8. 首条消息**禁止包含**链接、手机号、微信号、邮箱、图片，长度 ≤ 120 字。
9. 同一时段内不要连续投同一行业/同一城市超过 10 条，穿插不同城市与岗位类型。

## 10. 话术规则（2026-11-12 修订，项目专用）

> 本节只适用于 `D:\自动boss` 项目，不影响其他项目。

### 10.0 教训（2026-11-11 森恩案例）

- JD 写“公共数据库挖掘”，话术却说“序列数据库我能做”——两个不是一回事。
- JD 没提 NGS，话术却加了“NGS分析”。
- JD 提了“单细胞”，话术却没写单细胞。

结论：话术不是“JD 关键词 + 我的背景”的拼接，而是**严格从 JD 原文摘要求，再和候选人真实能力取交集**。

### 10.1 三条硬规则

1. **只写 JD 原文出现的要求**：JD 没写的技能，一个字都不能加。
2. **只写候选人真实具备的能力**：以 `data/candidate_profile.json` 的 `capabilities[].have=true` 为准；`have=false` 的（如公共数据库挖掘）不能写。
3. **JD 提到单细胞，话术必须包含单细胞**，并放在前三位。

### 10.2 能力映射（不能乱换同义词）

- 公共数据库挖掘（TCGA/GEO/NCBI）**≠** 序列数据库（专利序列库/数据库建设）。
- NGS 只在 JD 写 NGS / 高通量测序 / 二代测序 / 测序数据 / 基因测序 时才写。
- R/Python/Linux/Shell 要做独立词匹配，避免“HMMER、”被误判成 R 语言。
- 蛋白建模只匹配 蛋白建模 / 蛋白改造 / Rosetta / 分子对接 / CADD / 分子模拟；**不匹配**蛋白质组学。
- 宏基因组 **≠** 基因组分析；“宏基因组”不触发“基因组分析”。
- 单细胞优先：只要 JD 出现单细胞，单细胞分析强制进入前三。
- JD 的否定语境不算要求：出现“不做 / 不偏好 / 无需 / 不涉及 / 不要求 单细胞、转录组”等，
  不能把这些技能写进话术。
- **话术里不要写 R语言、Python、Linux、Shell 这类基础工具**；只写领域技术，
  覆盖率也只按领域技术计算。

### 10.3 模板（三条独立消息）

第一条（技能）：

```
{X总}您好，{JD 要求 ∩ 我会的技能 2–3 个}我都会。
```

第二条（科研智能体）：

```
而且我最近还成功研发了科研智能体，一个人能干十个人的活。
```

第二条可用同义变体，但**必须包含“而且”**；完整句库见 `docs/话术生成约束.md`。

第三条（请对方看简历）：

```
您可以看看我的简历吗？
```

- 称呼统一 `X总`，不写老师/经理。
- 口语化，不写公司介绍、不写客套废话。
- 每条尽量短：第一条 ≤45 字，第二条 ≤40 字，第三条 ≤20 字。
- 每个岗位 4 组变种（A/B/C/D，各三条），随机用；不得群发同一句。
- **必须是三条独立消息**：先发 -1，停 2–4 秒发 -2，再停 2–4 秒发 -3。

### 10.4 生成流程（强制）

1. 从 JD **正文**抽取要求（不要用 jobName、福利标签）。
2. 与 `candidate_profile.json` 的 `capabilities`（have=true）取交集。
3. 按 JD 出现顺序排序；单细胞强制置顶。
4. 取前 3 个生成话术。
5. 没有交集 → 话术留空，标“无匹配证据，建议跳过”。
6. 有经验缺口 → 标“需人工（缺口：X）”，不自动发。
7. 生成后必须跑 `python scripts/validate_greetings.py`，0 违规才允许进入发送队列。

### 10.5 示例（森恩修正）

- JD：公共数据库挖掘、单细胞、转录组、R 语言；**没有 NGS**。
- ❌ 旧：`孙总您好，序列数据库、转录组分析、NGS分析这几样我都会……`
- ✅ 新：`孙总您好，单细胞分析、R语言、转录组分析这几样我都会……`

### 10.6 候选人口径

- 单细胞：用户 2026-11-11 明确要求加入，已在 `candidate_profile.json` 的 `single_cell` 中登记。
- 公共数据库挖掘：目前 `have=false`，JD 提到也不能写；如用户确认具备，再改 `have=true`。
- 任何新增能力必须先改 profile，再生成话术；禁止在话术里临时编造。

### 10.7 老板 / HR 分表

- 分类：老板/一号位（A）、用人负责人（B）、HR（C）、猎头/代招（D）。
- 输出分文件：`BOSS投递审核表_老板直招_*.xlsx`、`BOSS投递审核表_HR招聘_*.xlsx`、`BOSS投递审核表_其他_*.xlsx`。
- **默认只投老板直招（A）**；HR、人事、招聘专员/经理、HRBP、泛称“招聘者”、猎头一律不投，
  除非用户明确说“可以投 HR”。
- **例外：非老板岗如果是兼职/日结/按单/完工结/长期兼职/可兼职，也可以投**；其他非老板不投。
- 老板直招默认全部发；校招/应届/博士等硬条件不符的，先提示用户，由用户决定是否破例。

### 10.8 审核与发送

- 审核表列：岗位核心要求 / 匹配证据 / 话术自检 / 经验缺口 / 话术 A-1..D-3。
- 只发“审核=通过”且“话术自检=通过”的行。
- **发送前按公司去重**：已经发过的公司（含同名、分子公司、截断名）不再投，命中即跳过。
- 发送节奏：随机 A/B/C/D；60–120 秒/职位；15 条/天；命中风控立即停。

### 10.9 适度补充（交集少时）

- 第一条与 JD 的交集 ≤2 时，允许补 1 个通用能力：生信流程开发 / Linux / Python / R语言 / 质控。
- 不能补领域技能（单细胞、NGS、蛋白组学等 JD 没提的方向）。
- 补了要在「话术自检」标“含补充”；校验器只对“含补充”的行放行这些通用能力。
- 这是“吹点牛”的边界：可以显得更全面，但不能编造项目或领域经验。

## 11. 回复监控（`scripts/monitor-replies.mjs`）

### 11.1 作用

发完招呼后，每 **3–5 分钟**读取一次 BOSS 消息列表，发现新回复就：

1. **写入当前 OpenCode 会话**（`session.synthetic`，`resume:false`），对话里会出现一条
   `🔔 BOSS 新回复（N 条）` 的消息，会话同时标记未读，方便你回来翻记录；
2. 弹 **Windows 桌面通知 + 提示音**（备用提醒）；
3. 写入 `data/replies.jsonl` 和 `data/replies_latest.md`；
4. 进程退出，让上层 Agent 收到通知并在聊天里汇报。

### 11.2 做法

- 只读消息列表，**不点开对话**（点开会标记已读，也会增加风控暴露面）。
- 首次运行只建立基线，**不会把历史未读当成新回复**。
- 新回复判定：`.notice-badge` 未读数变化，或最后一条消息内容变化，且不是自己发的（没有 `[送达]`）。
- 每轮都过 `checkPage()`；命中风险立即停止并冷却。
- 只在 07:00–23:00 运行；单次最多 4 小时，之后退出等重启。
- 会话 ID 存在 `data/notify_session.json`；文件不存在时自动选
  `D:\自动boss` 目录下最近更新的会话。换会话后删除该文件即可重新发现。

### 11.3 启动与停止

启动（后台）：

```powershell
ego-browser nodejs -e "await import('file:///C:/Users/Administrator/ego/run-monitor.mjs')"
```

停止：创建 `data/monitor.stop`（下一轮检查时退出），或直接结束该后台进程。

### 11.4 限制

1. OpenCode 与 ego 必须保持运行；ego 关闭则监控停止。
2. 用户接管 ego 任务空间时，浏览器命令会暂停。
3. 只能拿到**最后一条消息的预览**；看全文需要人工点开，或在用户同意后由 Agent 打开。
4. **不要和投递并发**：发招呼前先停监控，发完再启动。
5. 会话内消息走 `session.synthetic`，`resume:false`，不会触发模型回复；如果会话很忙可能失败，失败时仍会弹桌面通知并写日志。
6. 换到新的 OpenCode 会话后，删除 `data/notify_session.json` 让它重新发现，或手动写入新的会话 ID。

## 12. 信息展示规范（2026-11-12，项目专用）

展示岗位信息、话术、审核结果时，必须完整展示，不得只给摘要：

1. 基础信息：公司、岗位、城市/区域、薪资、经验、学历、招聘者+职务、行业/规模、职位链接。
2. 公司简介：完整一段，不要只给一句。
3. JD：全文原文，保留换行，放在代码块里；不得用“JD 核心/摘要”代替。
4. 话术：每条消息单独列出（-1 / -2）。
5. JD 被折叠时先点“展开”再抓取；抓完检查结尾是否完整。
6. 适用范围：审核表展示、发送前预览、结果汇报、任何用户要求“看看信息”的场景。
